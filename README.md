# حضور و غیاب من (Hozor)

اپلیکیشن موبایل حضور و غیاب با **تقویم شمسی**، ثبت ورود/خروج و گزارش کارکرد — دقیقاً بر اساس طرح داشبوردی که فرستادی.

- یک کدبیس، دو خروجی: **وب‌اپ نصب‌شدنی (PWA)** + پروژه آماده برای ساخت اپ نیتیو **اندروید و آیفون** با Capacitor.
- کاملاً فارسی، راست‌به‌چپ، فونت وزیرمتن، اعداد فارسی.

## امکانات

| بخش | توضیح |
| --- | --- |
| تقویم ماهانه | نمای هفت‌ستونی (شنبه تا جمعه) با شیفت، ساعت ورود/خروج، کارکرد، کسر کار، تاخیر و اضافه‌کاری هر روز؛ در موبایل به‌صورت لیست روزانه نمایش داده می‌شود |
| کارت‌های آماری | ساعت کاری، اضافه‌کاری تایید‌شده/تاییدنشده، کسر کار جلسات، خارج از شیفت، تعطیل‌کاری، تاخیر ماه، مرخصی و کارکرد کل |
| ثبت دستی روز | انتخاب روز از **تقویم شمسی**؛ چند جفت **ورود/خروج** (ورود اول، ورود دوم، سوم و چهارم) با محاسبهٔ لحظه‌ای کارکرد، موظفی، اضافه‌کاری و کسر کار؛ مرخصی (ساعتی/روزانه)، اضافه‌کاری تأییدشده، **تعطیل رسمی** و توضیح |
| ورود دوم | ثبت ورود/خروج دوم و بیشتر برای همان روز (بازگشت بعد از استراحت، ماموریت، جلسه) — هم در ویرایش روز و هم با دکمهٔ ثبت سریع |
| اضافه‌کاری با خط زرد | زیر ساعت کارکرد هر روز یک **خط زرد** با مقدار اضافه‌کاری (تأییدشده یا در انتظار) نشان داده می‌شود؛ در تقویم، در لیست روزهای موبایل و در صفحهٔ روز. تعطیل‌کاری با خط بنفش |
| مرخصی و تعطیل‌کاری | مرخصی ساعتی یا تمام‌روز، و علامت «تعطیل رسمی» که کارکرد آن روز را به‌جای کسر کار، تعطیل‌کاری/اضافه‌کاری حساب می‌کند |
| ثبت سریع | دکمه بزرگ با ساعت زنده، محاسبه لحظه‌ای کارکرد، حذف آخرین ثبت، ثبت اختیاری موقعیت مکانی |
| ثبت ورود و خروج در صفحهٔ ثبت دستی | دو دکمهٔ بزرگ **ثبت ورود** و **ثبت خروج** برای هر روز انتخابی (هر بار زدن = یک ثبت تازه، پس ورود دوم/سوم هم با همین دو دکمه)، ثبت با ساعت دلخواه، و لیست ثبت‌های همان روز با **ویرایش ساعت** و **حذف تک‌ثبت** |
| لمس روز در تقویم | صفحه‌ای باز می‌شود که می‌پرسد «ورود یا خروج؟»؛ بعد ساعت را می‌زنی و ثبت می‌شود. گزینه «ویرایش کامل روز» هم همان‌جاست (چند بازه، مرخصی، توضیح، پاک کردن) |
| شیفت شبانه (تا بامداد) | اگر ساعت پایان شیفت کوچک‌تر از شروع باشد (مثلاً ۰۸:۰۰ تا ۰۴:۰۰)، همه‌چیز به همان روز کاری نسبت داده می‌شود؛ ثبت ۰۲:۰۰ بامداد در روز بعد جدا حساب نمی‌شود |
| کنترل خروج فراموش‌شده | روزهایی که فقط ورود ثبت شده با برچسب «خروج ثبت نشده» مشخص می‌شوند و کارکرد تا پایان شیفت محاسبه می‌شود، نه تا نیمه‌شب |
| گزارش‌ها | نمودار کارکرد روزانه، ریز کارکرد، جمع‌بندی و میانگین‌ها |
| خروجی اکسل | فایل `.xlsx` واقعی (RTL) با همه روزهای ماه + جمع‌بندی؛ خروجی CSV هم موجود است |
| پروفایل | نام، واحد، ساعت شیفت، استراحت روزانه، انتخاب روزهای تعطیل هفته، تغییر رمز، بازنشانی دادهٔ نمونه |
| **حساب کاربری** | ورود/ثبت‌نام با ایمیل و رمز روی Supabase؛ هر نفر فقط سوابق خودش را می‌بیند (Row Level Security) |
| **همگام‌سازی** | سوابق روی سرور ذخیره می‌شود؛ بین گوشی و مرورگر یکی است. بدون اینترنت ثبت‌ها روی دستگاه می‌ماند و بعد از وصل شدن ارسال می‌شود. هنگام باز شدن اپ، دادهٔ گوشی با سرور **ادغام** می‌شود (نه جایگزین) تا هیچ ثبتی گم نشود؛ در صورت خطای ذخیره، بنر «تلاش دوباره» نمایش داده می‌شود |
| **ایمپورت از اکسل** | با لینک (گوگل‌شیت/درایو/دراپ‌باکس) یا فایل؛ تشخیص خودکار ستون‌های تاریخ، ورود، خروج، **ورود دوم، خروج دوم**، کارکرد، **مرخصی**، **اضافه‌کاری** و توضیح؛ پیش‌نمایش و انتخاب رفتار روزهای تکراری |
| آفلاین | داده‌ها در حافظه دستگاه کش می‌شوند و سرویس‌ورکر PWA نصب و اجرای بدون اینترنت را ممکن می‌کند |

## نصب اپ اندروید

آخرین نسخه آماده: **[بخش Releases](https://github.com/mazodimobinhost-creator/hozor/releases/latest)**

1. فایل `hozor-x.y.z.apk` را روی گوشی اندروید دانلود کن.
2. اگر پیام «نصب از منابع ناشناس» آمد، اجازه بده.
3. نصب کن. از این به بعد هر نسخه جدید روی همین اپ به‌روزرسانی می‌شود و اطلاعات می‌ماند.

نسخه iOS: همین اپ را با Safari به صفحه اصلی اضافه کن، یا با Xcode بساز (`MOBILE.md`).

## به‌روزرسانی از داخل اپ

- **PWA:** سرویس‌ورکر نسخه جدید را پیدا می‌کند و پیام «نسخه جدید اپ آماده است — بروزرسانی» بالای صفحه می‌آید.
- **اپ اندروید/آیفون:** هنگام باز شدن اپ، نسخه‌ها با GitHub Releases مقایسه می‌شود؛ اگر نسخه تازه‌تری باشد بنر «نسخه x آماده است — دریافت» نمایش داده می‌شود. مسیر دستی: پروفایل ← «بررسی بروزرسانی».
- APK با یک **کلید امضای ثابت** (`signing/hozor-release.p12`) ساخته می‌شود تا نسخه جدید روی نسخه قبلی نصب شود، نه به‌صورت اپ دوم.

### انتشار نسخه جدید

```bash
# نسخه را در package.json بالا ببر (مثلاً 1.0.2)، سپس:
git tag v1.0.2 && git push origin v1.0.2
```

ورک‌فلوی `Build Android APK` خودش APK امضاشده را می‌سازد و روی همان تگ به Releases می‌چسباند؛ اپ‌های نصب‌شده هم بلافاصله آن را پیشنهاد می‌دهند.

راهنمای کامل: [`MOBILE.md`](./MOBILE.md)

```bash

npx cap add android      # و یا npx cap add ios

```

## محاسبات

- **کارکرد روز** = جمع بازه‌های ورود تا خروج (بدون استراحت‌های بین آن‌ها).
- **کارکرد داخل شیفت** = هم‌پوشانی کارکرد با بازه شیفت (پیش‌فرض ۰۸:۰۰ تا ۱۷:۰۰).
- **خارج از شیفت** = کارکرد منهای هم‌پوشانی با شیفت.
- **موظفی روزانه** = طول شیفت منهای استراحت روزانه (قابل تغییر در پروفایل).
- **شیفت شبانه:** اگر `پایان شیفت ≤ شروع شیفت` باشد، پایان به‌صورت «+۲۴ ساعت» در نظر گرفته می‌شود؛ مثلاً ۰۸:۰۰ تا ۰۴:۰۰ یعنی ۲۰ ساعت شیفت. ثبت‌های بامداد (۰۰:۰۰ تا ساعت پایان) به روز کاری قبل تعلق می‌گیرند.
- **تاخیر** = دیرتر از شروع شیفت بودن اولین ورود.
- **اضافه‌کاری** = کارکرد مؤثر (کارکرد + مرخصی + جلسه) منهای موظفی؛ در روز تعطیل، تمام کارکرد.
- **اضافه‌کاری تاییدنشده** = اضافه‌کاری منهای مقدار تاییدشده در همان روز.

## ساختار پروژه

```
src/
  lib/
    jalali.ts     تبدیل و قالب‌بندی تاریخ شمسی، اعداد فارسی
    calc.ts       محاسبه کارکرد، تاخیر، اضافه‌کاری و آمار ماه
    store.tsx     حالت اپ: کش محلی + همگام‌سازی با Supabase + صف آفلاین
    supabase.ts   ساخت کلاینت Supabase (URL و anon key)
    auth.tsx      ورود، ثبت‌نام، خروج، بازیابی رمز
    remote.ts     خواندن/نوشتن جدول‌های profiles و day_records (RLS)
    importer.ts   خواندن اکسل، تشخیص ستون، تبدیل تاریخ شمسی/میلادی و ساعت
    fileFetch.ts  گرفتن فایل از لینک + پروکسی تابع ابری
    export.ts     خروجی اکسل و CSV
  components/     تقویم، کارت‌های آماری، صفحه ثبت، گزارش‌ها، ایمپورت، پروفایل، ورود
  styles.css      طراحی واکنش‌گرا (RTL)
```

## حساب کاربری و حریم خصوصی

- هر نفر با ایمیل و رمز خودش وارد می‌شود؛ **هیچ‌کس به داده دیگری دسترسی ندارد**.
- امنیت در سطح دیتابیس با **Row Level Security** اعمال می‌شود: حتی اگر کسی درخواست را دستکاری کند، فقط ردیف‌های `user_id = auth.uid()` برگردانده می‌شود.
- پشتیبان‌گیری، همگام‌سازی بین گوشی/مرورگر و ادامه کار روی گوشی دیگر خودکار است.
- داده‌های نسخه قدیمی (قبل از لاگین) که روی دستگاه مانده است، بعد از اولین ورود به‌صورت یک پیشنهاد برای انتقال به حساب نمایش داده می‌شود (نه خودکار).
- جزئیات پروژه Supabase: پوشه [`supabase/`](./supabase/README.md).

## متغیرهای محیطی (اختیاری)

اگر می‌خواهید به پروژه Supabase دیگری وصل شوید، در Vercel یا فایل `.env.local`:

```
VITE_SUPABASE_URL=https://<project>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon key>
```

مقادیر پیش‌فرض پروژه فعلی داخل `src/lib/supabase.ts` هستند (کلید anon عمومی است؛ امنیت با RLS است).

## انتشار روی GitHub Pages (لینک دائمی برای آیفون و اندروید)

آدرس ثابت: `https://mazodimobinhost-creator.github.io/hozor/`

ورک‌فلوی `.github/workflows/pages.yml` با هر push روی `main`:

1. اپ وب را با `BASE_PATH=/hozor/` می‌سازد و بستهٔ جداگانه‌ای برای APK با `base=/` (وگرنه اپ اندروید صفحه سفید می‌شد).
2. APK امضاشده را می‌سازد و کنار خروجی وب در `dl/hozor.apk` می‌گذارد.
3. همان APK را روی یک‌دو **آینه عمومی** (catbox / 0x0) هم آپلود می‌کند و لیست آینه‌ها را در `dl/mirrors.json` می‌نویسد.
4. کل خروجی را روی برنچ `gh-pages` منتشر می‌کند (منبع Pages باید روی همین برنچ تنظیم باشد).

اگر GitHub Pages روی ریپو فعال نباشد، یک بار در `Settings → Pages` گزینه **Deploy from a branch → gh-pages / (root)** را انتخاب کن.

- فایل نصبی اندروید: `https://mazodimobinhost-creator.github.io/hozor/dl/hozor.apk`
